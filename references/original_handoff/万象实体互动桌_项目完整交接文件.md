## 一 项目是什么

### 1.1 一句话定义

万象实体互动桌是一套使用无源磁吸互动片、顶部视觉识别和单套 XY 自动移动机构的通用实体交互平台。同一个桌面底座可通过更换互动片和软件内容，切换为棋类游戏、桌游、亲子教育、二次元角色互动和家庭陪伴设备。

### 1.2 项目来源与差异化

项目受到 Chessnut Move 自动棋盘启发，但目标不是复制一块低价国际象棋棋盘，而是把“识别实体物体并自动移动”的能力做成通用平台。

与 Chessnut Move 相比，项目的预期差异如下：

| 项目 | Chessnut Move | 万象实体互动桌 |
|---|---|---|
| 主要载体 | 国际象棋棋子 | 通用磁吸互动片、角色片、任务块 |
| 应用范围 | 国际象棋为主 | 棋类、桌游、教育、陪伴、二次元 |
| 驱动思路 | 完整商业自动棋盘 | 单套 XY 滑台集中驱动 |
| 显示方式 | 棋盘与配套软件 | 手机或网页为主，底座提供实体反馈 |
| 成本目标 | 高端消费产品 | 学生样机约 700 至 1100 元 |
| 内容扩展 | 棋谱、平台对弈 | 可更换角色、规则和主题内容包 |

### 1.3 核心产品体验

1. 用户把带磁铁或铁片的互动片放到棋盘上。
2. 顶部摄像头通过 ArUco 标记识别互动片身份和所在格子。
3. 电脑或手机端运行游戏规则、AI 或角色任务逻辑。
4. 控制端向 ESP32-S3 下发移动指令。
5. ESP32-S3 控制两轴步进电机，将电磁铁移动到互动片下方。
6. 电磁铁吸合互动片并移动到目标格，完成实体反馈。
7. 网页显示状态、棋局、角色内容和设备日志。

## 二 产品路线

### 2.1 第一阶段 MVP

第一阶段只完成以下闭环：

- 8×8 实体棋盘。
- 5 至 10 枚无源磁吸互动片。
- 顶部 USB 摄像头识别 ArUco 标记。
- 单套 XY 滑台和一个电磁铁。
- ESP32-S3 负责电机、电磁铁、限位和通信。
- 电脑端运行五子棋规则和 AI。
- 玩家落子后，系统识别位置，AI 计算一步，底座自动移动白色互动片。
- 网页保留手动控制和演示状态。

第一阶段不应同时做语音、账号、云端记忆、支付、商业 IP、多棋种联网和量产外壳。

### 2.2 第二阶段产品化

- 将开发板和模块整合为自绘 PCB。
- 从摄像头识别升级为霍尔阵列，或采用视觉与霍尔融合。
- 加入 NFC 角色卡匣，用于主题、人物和内容授权。
- 加入灯光、声音、旋钮和更完整的异常处理。
- 增加国际象棋、中国象棋、亲子任务等内容。
- 完善外壳、互动片和桌面的工业设计。

### 2.3 长期商业形态

- 基础主机：棋类和通用互动能力。
- 棋类包：棋盘面板、互动片和规则软件。
- 二次元角色包：原创角色卡、主题互动片、角色语音和剧情任务。
- 教育包：识字、算术、英语和编程启蒙任务。
- 家庭陪伴包：异地同步、亲子任务和纪念互动片。
- 机构版：面向学校、桌游店和养老机构的内容与管理工具。

## 三 系统架构

```text
无源互动片
   ↓ 摄像头画面
OpenCV / ArUco 识别
   ↓ 棋盘状态
游戏规则或角色逻辑
   ↓ 目标移动
总控程序
   ↓ BLE 或串口指令
ESP32-S3 固件
   ↓
A4988 × 2 → XY 步进电机
MOSFET → 12 V 电磁铁
限位开关 → 安全保护
```

### 3.1 机械层

- XY 同步带滑台或直线模组。
- 两个 NEMA17 步进电机。
- A4988 驱动器两块。
- 滑台下方或内部电磁铁。
- 亚克力或木质上层棋盘。
- 互动片底部磁铁或铁片。

### 3.2 感知层

- 第一版：顶部摄像头和 ArUco 标记。
- 已预留：少量霍尔传感器用于验证磁场或辅助检测。
- 四个限位开关用于回零和行程保护。

### 3.3 控制层

- ESP32-S3 DevKitC-1。
- PlatformIO 和 Arduino 框架。
- AccelStepper 控制运动。
- NimBLE-Arduino 提供 BLE GATT 服务。

### 3.4 内容层

- 五子棋规则与 Minimax AI。
- python-chess 和 Stockfish 国际象棋接口。
- 网页 BLE 手动控制端。
- 独立产品动态演示页面。

## 七 已知问题和风险

### P0 必须先修复

#### 7.1 固件参数解析错误

固件把命令解析为：

```text
MOVE,X,50,Y,0
→ ["MOVE", "X", "50", "Y", "0"]
```

但是 `CommandParser::getArg` 从索引 0 开始、每次增加 2，实际检查的是 `MOVE` 和 `50`，不会检查索引 1 的 `X`。因此网页发送的 MOVE、GRID 等键值命令可能全部得到默认值 0。

建议修复：从索引 1 开始按键值对扫描。

```cpp
for (size_t i = 1; i + 1 < args.size(); i += 2) {
    if (args[i] == key) return args[i + 1];
}
```

修复后必须为以下命令增加解析测试：

```text
MOVE,X,200,Y,-100
GRID,ROW,3,COL,4
GOTO,X,1000,Y,500
```

#### 7.2 缺少真正的总控程序

当前 `camera_recognition.py`、五子棋 AI、国际象棋接口、网页控制端和 ESP32 固件相互独立。工程中没有一个程序完整执行以下流程：

```text
读取摄像头
→ 识别玩家新落子
→ 更新游戏状态
→ 计算 AI 落点
→ 选择可用互动片来源
→ 发送 PIECE 指令
→ 等待 OK,PIECE_DONE
→ 再次识别并核对结果
```

建议新建：

```text
pc/controller.py
pc/device_transport.py
pc/state_reconciler.py
```

这是当前最重要的开发任务。

#### 7.3 ESP32-S3 引脚需要重新核对

当前配置使用 GPIO25、26、27、32、34、35、36、39 等引脚。ESP32-S3 DevKitC-1 N16R8 的部分引脚可能不存在、未引出或被 Octal Flash/PSRAM 占用。不能按文档直接接线。

接手后必须根据手中开发板的准确型号和官方引脚图重新分配：

- 两组 STEP、DIR、ENABLE。
- 四个限位输入。
- 电磁铁 MOSFET 控制。
- 蜂鸣器或 LED。

每个引脚应记录“是否引出、是否启动绑带、是否被 Flash/PSRAM 占用、是否支持内部上拉”。

#### 7.4 缺少软件限位和回零超时

普通 MOVE、GOTO、GRID 命令没有统一的目标范围限制。回零函数使用阻塞循环，如果限位开关未接好，电机会持续运行并卡死程序。

必须增加：

- X/Y 软件最小值和最大值。
- GRID 行列范围 0 至 7 检查。
- 回零超时。
- 限位触发立即停止。
- STOP 指令可中断正在执行的运动。
- 上电未回零时禁止绝对坐标移动。

### P1 应在实物装配前修复

#### 7.5 文档与固件指令格式不一致

快速开始文档写的是：

```text
MOVE X 100
MAG ON
```

固件实际只按逗号解析：

```text
MOVE,X,100
MAG,ON
```

必须统一文档、网页、串口工具和固件，建议全部使用逗号协议。

#### 7.6 PIECE 协议依赖硬编码下标

当前固件通过 `args[2]`、`args[3]`、`args[5]`、`args[6]` 读取：

```text
PIECE,FROM,3,2,TO,5,4
```

这种方式可以工作，但缺少长度、数字、范围和关键字校验。收到损坏命令可能抛异常或移动到错误位置。

建议将协议固定为：

```text
PIECE,FROM_ROW,3,FROM_COL,2,TO_ROW,5,TO_COL,4
```

或者保留短格式，但为它写独立解析函数和错误响应。

#### 7.7 8×8 硬件与 15×15 五子棋不一致

固件配置是 8×8，五子棋引擎默认是 15×15。必须选择一条路线：

- MVP 使用 8×8 简化五子棋，并明确这是演示玩法。
- 将实体桌扩大为 15×15，但机械行程和成本都会增加。
- 使用分页或虚拟棋盘，不适合第一版实体体验。

当前建议选择 8×8 MVP，优先证明闭环。

#### 7.8 摄像头未标定时映射不可靠

`camera_recognition.py` 未标定时把整张 1280×720 画面映射到棋盘。只要棋盘没有铺满画面、发生倾斜或摄像头偏移，格子就会判错。

应保存并加载四角标定结果，例如：

```text
config/calibration.json
```

并加入画面有效区域、置信度、重复标记和同格冲突处理。

#### 7.9 机械文件并不完整

`hardware/3D_models/` 只有 README，没有 STL、STEP、DXF 或 CAD 源文件。项目暂时不能直接加工机械结构。

必须补齐：

- 底座尺寸图。
- 滑台固定件。
- 电磁铁支架。
- 棋盘上盖。
- 摄像头支架。
- 互动片外壳。
- 装配爆炸图和螺丝清单。

### P2 产品化问题

- 电磁铁连续吸合的温升需要实测，30 秒保护值没有实验依据。
- A4988 电流设置不能只依赖“约 0.5 V”，应按具体模块采样电阻计算。
- 12 V 电磁铁必须使用 MOSFET、栅极电阻、下拉电阻和续流二极管。
- BOM 中 ESP32-CAM 与“顶部 USB 摄像头”的路线不一致，应二选一。
- 当前网页控制端主要是调试工具，不是最终消费者界面。
- 使用商业二次元 IP 会产生版权风险，答辩和原型建议使用原创角色。
- Stockfish 为 GPLv3，发布集成版本时要遵守许可证。

## 八 推荐的统一通信协议

第一版可以使用简单 ASCII 行协议，每条命令以换行结束。

| 方向 | 命令 | 含义 |
|---|---|---|
| 主机到设备 | `STATUS?` | 查询坐标、电磁铁和状态 |
| 主机到设备 | `HOME` | X/Y 两轴回零 |
| 主机到设备 | `GRID,ROW,3,COL,4` | 移动滑台到目标格 |
| 主机到设备 | `PIECE,FROM,3,2,TO,5,4` | 搬运互动片 |
| 主机到设备 | `MAG,ON` | 电磁铁吸合 |
| 主机到设备 | `MAG,OFF` | 电磁铁释放 |
| 主机到设备 | `SPEED,1200` | 设置最大速度 |
| 主机到设备 | `STOP` | 紧急停止并释放电磁铁 |
| 设备到主机 | `OK,HOME_DONE` | 命令完成 |
| 设备到主机 | `OK,PIECE_DONE` | 互动片移动完成 |
| 设备到主机 | `ERR,RANGE` | 目标越界 |
| 设备到主机 | `ERR,NOT_HOMED` | 尚未回零 |
| 设备到主机 | `ERR,LIMIT` | 限位触发 |
| 设备到主机 | `STATUS,X:0,Y:0,MAG:OFF,READY` | 状态返回 |

主机必须等待设备返回完成消息后再更新最终棋盘状态。超时后进入错误状态，不应假定动作成功。

## 九 预算与采购状态

### 9.1 BOM 现状

原 BOM 的数字项合计约 698 元，README 给出的标准版预算约为 750 至 1100 元。该估算未充分覆盖以下成本：

- 机械件重复打印和改版。
- 电源保护、MOSFET 小板和连接器。
- 摄像头支架。
- 亚克力或木板加工。
- 备用 A4988、步进电机和电磁铁。
- 万用表、焊接和压接工具。
- 运输和小批量加工费用。

建议首轮准备 900 至 1200 元预算，并分批采购。

### 9.2 建议采购顺序

第一批，只验证电子与运动：

- ESP32-S3 开发板。

- 小型 12 V 电磁铁。
- 四个限位开关。

第二批，验证视觉和棋盘：

- 小尺寸 XY 滑台或自制同步带结构。
- 棋盘上盖材料。

第三批，结构稳定后再购买：

- 定制亚克力或木板。
