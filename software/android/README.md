# Android 调试端与后续前端

当前定位是调试端和协议验证端，前端最终可以是 Android 或微信小程序。屏幕流程：扫描设备 → 连接 → 请求完整快照 → 显示棋盘 → 等待玩家/磁力台架 → 显示或播报 AI 走法 → 等待实体落子确认 → 更新记录。

最小功能：BLE 连接、8×8 棋盘、同步状态、难度设置、语音开关、FEN/PGN 本地记录、错误和重新同步。暂不做账号、云端、远程联机和复杂聊天。

当前无触点版本的连接流程：

1. 扫描并连接 ESP32-S3 自定义 GATT 服务。
2. 发送 `SNAPSHOT?`，接收读头 UID/坐标记录并换算格位；触点基线仍可使用同一快照字段。
3. 首次使用进入“棋子登记”：逐枚读取 NTAG213 UID，选择颜色和角色；若回退到 DS2431，再使用独立写入夹具。
4. AI 走法进入 `WAIT_CONFIRM` 后，只有同一 UID 从源格到目标格才推进逻辑局面。

Android 12 及以上需要在运行时申请 `BLUETOOTH_SCAN` 和 `BLUETOOTH_CONNECT`；不做账号和云端登录。微信小程序是否作为正式前端，待 BLE 连接、断线恢复和权限行为实测后决定。Stockfish 作为本地 UCI 引擎，先限制搜索深度和思考时间。
