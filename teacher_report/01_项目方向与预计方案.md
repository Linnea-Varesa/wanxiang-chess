# 项目方向与预计方案

**时间 tag：`2026-09-18T18:50+08:00`**
**适用周期：`2026-09-19` 至 `2026-12-31`**

## 方向冻结

项目做个人使用的国际象棋实体互动桌，核心方向是棋子在平滑棋盘上可被识别，自动移动作为后续创新方向。先解决“棋子是谁、棋子在哪一格”，主链路不使用摄像头视觉识别。

## 分层方案

| 层 | 首版方案 | 年底要证明的内容 |
|---|---|---|
| 棋子 | 3D 打印可拆底盖；被动 NTAG213 标签或磁编码盘 | 单枚 UID 可读；标签、磁体和底座不互相干扰 |
| 棋盘感知 | 平滑非金属面；小型读头/位置层；DS2431 触点为回退基线 | 2×2 能区分四格，争取 4×4；记录扫描周期和串读 |
| 主控 | ESP32-S3 | 固件可烧录、扫描、去抖、生成快照、BLE 传输 |
| 前端 | Android 调试端；微信小程序后置候选 | 固定协议，后续选择合适交互端 |
| AI | 手机本地 Stockfish/UCI 或同类引擎 | 至少 3 档难度，能返回合法走法 |
| 自动移动 | 只预留下方磁力耦合、状态字段和机械接口 | 2026 年不做实物；下一年度再评估单棋子台架 |

## 用户流程

1. APP 读取或载入棋局快照。
2. AI 计算下一步并输出颜色、棋子、源格和目标格。
3. 手机语音或棋盘屏幕提示走法。
4. 玩家手动放置，读头或位置层确认 UID 和格位。
5. APP 校验合法性和 UID 一致性；错误时提示重新放置，不猜测局面。
6. 玩家完成自己的回合，APP 再请求 AI。

## 关键判定

- 若标签读距不足或出现相邻格串读，先调整线圈、棋盘厚度和读头结构；不直接采购 64 格阵列。
- 若标签在相邻格串读或读距不足，先调整线圈、棋盘厚度和位置层；不直接采购 64 格阵列。
- 只有 2×2 无触点数据稳定后，才决定是否扩到 4×4 或 8×8；运动板不列入今年采购。
- Android 和微信小程序都先使用固定快照；真实前端在 BLE 协议稳定后再确定。
