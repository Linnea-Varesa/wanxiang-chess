# 05 棋子身份识别实验

> 方向更新：三个月版本不采用摄像头识别。主实验是“棋子底部一线制唯一 ID + 棋盘逐格触点读取”；无接触 NFC 只保留为对比实验。

## 核心判断

棋子 UID 只回答“是哪一枚棋子”，不能单独回答“在哪个格”。必须验证 UID 与 8×8 格位的联合识别。身份标签、磁体、铁片、面板厚度、铜层和相邻天线会互相影响。

## 推荐路线

首轮用最终外形的 8–16 枚棋子，在底部安装 DS2401+ 一线制唯一 ID 芯片和旋转不敏感的两触点。棋盘用 2×2、再到 4×4 的触点阵列，通过 74HC4067 选择格位。不要在未完成小阵列实验前设计 8×8 固定 PCB。

DS2401 只提供唯一身份，不携带“这是白兵”这样的永久角色。UID 与颜色、角色、升变状态由 Android 本地数据库绑定。

## 实验分级

### E05-1 单子材料和触点测试

记录芯片型号、UID、触点形状、旋转角度、偏心量、底板材料、弹簧针压力、读时长、漏读和误读。

### E05-2 2×2/4×4 联合定位

覆盖空位、相邻棋子、偏心、旋转、抬起、落下、多个棋子同时摆放、不同角色底座和触点氧化。输出每格的 ID、空位和置信度。

### E05-3 连续性与故障

连续扫描至少 100 次，统计每格成功率、邻位串读、单次扫描时间、整阵列周期、重试后成功率。任何“读到 UID 但坐标不确定”的结果都算失败。

### E05-4 扩展到 8×8

先做一条边或一个 4×4 分区，再扩全盘。记录多路器导通电阻、1-Wire 上升沿、布线和触点维护成本。全盘通过条件应包括识别结果可复现，而非只展示一次成功。

## 数据模型

```json
{
  "uid": "piece-017",
  "side": "white",
  "role": "pawn",
  "square": "e2",
  "confidence": 0.98,
  "observed_at": "2026-09-09T00:00:00Z"
}
```

`uid`、`role`、`square` 分开存储。升变时角色变化；备用棋子或替换棋子不能复用“UID 永久等于兵”的假设。

## 通过条件

- 至少 2×2/3×3 规模下能同时正确关联 ID 与格位。
- 空位、邻位、偏心、旋转、抬起、放下均有定义行为。
- 对连续扫描、错误 ID、读不到和冲突有重试或暂停策略。
- 使用未来磁吸结构的材料做测试，避免后期返工。
