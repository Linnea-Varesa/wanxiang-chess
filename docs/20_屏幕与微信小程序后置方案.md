# 棋盘屏幕与微信小程序后置方案

**时间 tag：`2026-09-18T18:35+08:00`**

## 棋盘屏幕可行性

可以实现。ESP32-S3 有足够的 SPI、GPIO 和内存驱动一个小型 TFT 屏幕，屏幕可以显示：

- 当前回合、玩家颜色和难度；
- AI 给出的走法和语音提示文字；
- 设备连接、扫描进度、读取错误和暂停状态；
- 后续自动移动的执行状态和故障提示。

首轮建议使用 `2.8 inch ILI9341 SPI 240×320` 模块，要求卖家明确 3.3 V 逻辑兼容。暂不购买带复杂触摸层的屏幕，先验证显示、供电和与传感/运动接口的引脚隔离。若需要更大界面，再评估 `3.5 inch ILI9488 480×320`；它的刷新和显存要求更高，不作为首批器件。

屏幕不应占用身份读头、运动限位和调试串口的专用引脚。实际 GPIO 分配要等 ESP32-S3 开发板实物到手后填写 [`../hardware/pinouts/主控引脚表.md`](../hardware/pinouts/主控引脚表.md)。

## 微信小程序可行性和边界

微信小程序可以作为后期交互层候选，微信提供 BLE 扫描、连接、服务发现和特征读写接口。它能减少单独维护 Android 页面带来的界面适配工作，但不能完全消除平台差异：蓝牙权限、系统后台限制、机型兼容性、调试工具和小程序审核约束仍需要实测。

因此当前不把 Android 或微信小程序写死为硬件接口。先固定 BLE/串口消息协议和棋局数据模型，使用 PC/Android 模拟器完成规则、AI 和识别流程；后期再把同一协议接入微信小程序。

## 后置实施顺序

1. 先完成无触点身份/定位实验和 ESP32 快照协议；
2. 再用 2.8 inch ILI9341 做棋盘状态屏；
3. 设备闭环稳定后，验证微信 BLE API 的连接、断线恢复和数据吞吐；
4. 最后决定微信小程序是否作为正式交互端，Android 是否保留为调试工具。
