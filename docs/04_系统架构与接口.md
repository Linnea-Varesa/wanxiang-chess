# 04 系统架构与接口

## 数据流

```text
棋子标签/位置传感
        ↓
识别层：UID + 格位 + 置信度 + 时间戳
        ↓
状态协调层：去抖、局面快照、异常恢复
        ↓
国际象棋规则层：合法性、胜负、特殊规则
        ↓
AI 适配层：返回逻辑走法，不操作硬件
        ↓
表达层：Android 显示 + 语音指导
        ↓（V1.5）
运动执行层：临时停车、磁吸、路径、到位复核
```

## 单一可信状态

软件保存三种状态：

1. `logical_position`：已确认的国际象棋局面，使用 FEN/内部模型表示。
2. `sensed_position`：最近一次稳定识别的 UID—格位快照。
3. `physical_task`：正在执行的提示或运动任务，以及命令 ID、阶段和超时。

只有识别稳定、规则合法、执行确认完成后，才能把逻辑局面推进到下一版本。手动打乱棋盘时进入 `UNSTABLE`，不得猜测用户意图继续下棋。

## 首版 BLE/串口协议

开发初期串口优先，BLE 复用同一行协议或同一消息字段。每个消息包含协议版本、设备 ID、棋局 ID、状态版本、命令 ID 和错误码。

设备到主机：

```text
HELLO,VER,1,DEVICE,wx-001
SNAPSHOT,STATE,12,P08:e2,P17:g1,...
EVENT,LIFT,PIECE,P08,FROM,e2,SEQ,91
EVENT,PLACE,PIECE,P08,TO,e4,SEQ,92
OK,CMD,41,RESULT,SNAPSHOT
ERR,CMD,41,CODE,NOT_STABLE
```

主机到设备：

```text
STATUS?,CMD,41
SNAPSHOT?,CMD,42
VOICE,KEY,move_knight_g1_f3,CMD,43
MOTION,FROM,e2,TO,e4,CMD,44
STOP,CMD,45
```

V1 可以只实现 `STATUS?`、`SNAPSHOT?`、事件上传和 BLE 心跳；运动命令在 V1.5 才开放。

## Android 功能边界

- 扫描和连接设备。
- 显示 8×8 棋盘、棋子角色和同步状态。
- 设置难度、语音开关、音量和本地 AI/联网后备策略。
- 显示当前建议走法、错误提示和恢复按钮。
- 保存本地对局记录、FEN/PGN 和故障日志。
- 断线重连后先请求完整快照，再应用增量事件。

## 必须处理的状态

`SETUP`、`WAIT_PLAYER`、`LIFTED`、`UNSTABLE`、`THINKING`、`VOICE_GUIDANCE`、`WAIT_CONFIRM`、`MOTION`、`PAUSED`、`RESYNC`、`GAME_OVER`。
